# Rover Lab — Sci-Fi конфігуратор і тест-лаб марсохода

3D-лабораторія на **React Three Fiber**: користувач збирає марсохід із запчастин (корпус, колеса, сенсори, інструмент), фарбує його і випробовує на полігоні з фізикою **Rapier**.

## Можливості

| Вимога | Реалізація |
| --- | --- |
| Зміна деталей «на льоту» | 3D-маркери на моделі відкривають список деталей; нова деталь «падає» на місце з анімацією (`ExplodablePart` + `replayKey`) |
| Exploded view | Кнопка **Розібрати** / клавіша **E**: корпус розділено на раму, начинку (батареї, бортовий комп'ютер, RTG), кришку, панелі; деталі плавно розлітаються, і видно внутрішню будову |
| Фізика керування | `@react-three/rapier` + `DynamicRayCastVehicleController`: підвіска, зчеплення, привід на всі колеса, рульове керування (у 6-колісних — задня вісь із протилежним кутом повороту) |
| UI у 3D-просторі | `<Html>` з drei: маркери слотів і пікер деталей, голографічна панель характеристик (`transform`), телеметрія над ровером на полігоні |
| Фарбування | Колір корпусу та акценту, тип покриття (матовий / сатин / метал); збірка зберігається в `localStorage` |
| Полігон | Рампи, пагорби, поле з горбами, скелі, піраміда ящиків і конуси, які можна збити; гравітація Марса, Місяця або Землі |

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # typecheck + production build
npm test           # unit- та фізичні тести (Vitest)
npm run lint
```

**Керування на полігоні:** `W/S` або `↑/↓` — газ і задній хід, `A/D` або `←/→` — кермо, `Пробіл` — гальмо, `R` — респавн.

## Архітектура

```
src/
├── types/vehicle.ts        Доменні типи: деталі, збірка, фарба
├── data/                   Статичні дані: каталог деталей, палітра, траса, гравітація
├── domain/                 Чиста логіка без React і Three.js
│   ├── build.ts            resolve/sanitize збірки
│   ├── stats.ts            Характеристики (маса, швидкість, рейтинги)
│   ├── vehicleSpec.ts      Збірка → фізичні параметри (колеса, підвіска, маса, інерція)
│   └── terrain.ts          Детермінована генерація скель
├── physics/                Шар над Rapier
│   ├── drive.ts            Ввід гравця → команди коліс (чиста функція)
│   └── vehicle.ts          Налаштування vehicle controller і маси шасі
├── store/                  Zustand: buildStore (persist), labStore (режим, UI)
├── lib/                    Утиліти: math, seeded random, текстури, хоткеї
└── components/
    ├── canvas/             Experience (перемикач сцен), світло, SceneHtml
    ├── rover/              Візуальна модель: матеріали, exploded view, деталі
    ├── garage/             Сцена гаража, 3D-маркери, голограма характеристик
    ├── testlab/            Фізичний полігон: рельєф, перешкоди, ровер, камера, телеметрія
    └── ui/                 2D HUD, пікер деталей, фарбування
```

Ключові рішення:

- **Дані окремо від логіки, логіка окремо від рендера.** Каталог деталей описано декларативно, а `buildVehicleSpec` перетворює вибрані деталі на фізичні параметри. Візуальна модель і фізика беруть розміри з одного джерела, тому колеса завжди стоять там, де їх «бачить» симуляція.
- **Фізика покрита тестами.** `vehicle.test.ts` запускає безголову симуляцію Rapier із тим самим кодом налаштування, що й React-компонент. Тести перевіряють, що кожна комбінація корпусу й коліс стає на всі колеса, їде вперед і назад, повертає в правильний бік і не перекидається в довгому повороті на повному газу.
- **Анімації не викликають ре-рендерів React.** Прогрес exploded view, оберти коліс і телеметрія оновлюються через `useFrame` і refs. Телеметрія пише значення прямо в DOM з обмеженою частотою.
- **Спільні матеріали.** `RoverMaterialsProvider` створює один набір матеріалів, а зміна фарби лише змінює їхні властивості, без перекомпіляції шейдерів. Повторювані елементи (протектори, шипи, скелі) малюються через `<Instances>`.
- **Code splitting.** Сцена полігона разом із WASM-модулем Rapier (~2 МБ) завантажується лише тоді, коли користувач переходить на полігон (`React.lazy`).
- **Стабільний портал для `<Html>`.** Усі 3D-прив'язані DOM-елементи рендеряться в окремий шар `.scene-overlay` через `SceneHtml`. Інакше drei може змінити контейнер після першого рендера, і тоді маркер виявляється порожнім або падає `removeChild` під час демонтажу.
- **Недовірені дані зі сховища.** Збереженій у `localStorage` збірці не довіряємо: її перевіряють проти каталогу (`sanitizeBuild`, `sanitizePaint`).
